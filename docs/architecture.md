# 架构：双机 + 三级智能体分流

## 设计目标

1. **便宜**：能本地办到的绝不调云 API；云只做决策和兜底。
2. **快**：实时/重活（生成、视觉、编码）走 GPU 副机，不占用主机 CPU。
3. **稳**：单机放不下大模型，就用双机分工；云断了本地还能兜底。
4. **可控**：任何人不能"自作主张上云烧钱"，搞不定的回人类拍板。

## 双机拓扑

```
┌─────────────── 主机（核显 CPU，如 AMD 780M / Ryzen）───────────────┐
│ OpenClaw 网关        llama-swap @8087             本地知识库          │
│  ┌──────────────┐    ├─ qwen3:30b   主力长文      (可选 ChromaDB)    │
│  │ L1 决策 agent │    ├─ qwen3:8b    日常                          │
│  │ L2 调度 agent │    └─ qwen2.5:1.5b 极快格式化                    │
│  └──────────────┘                                                  │
└──────────────────────────┬─────────────────────────────────────────┘
                           │ agent 间派单（HTTP/WS）
                           ▼
┌─────────────── 副机（独立 GPU，12GB+ 显存）─────────────────────────┐
│ llama-swap @11440（OpenAI-compatible 端点）                        │
│  GPU 组：instruct-14b / coder-14b / vl-7b / hermes2pro-8b         │
│  CPU 组：qwen3:8b（长文本汇总，不占 GPU）                           │
└────────────────────────────────────────────────────────────────────┘
```

### 为什么双机

- **主机**：CPU 强、内存大（64GB 级别），适合**同时常驻多个小模型**（30B/8B/1.5B 可同时 loaded，切换仅路由转发，无重载开销）。
- **副机**：有独立 GPU，但显存有限（12GB 级别，**塞不下第二个大模型**，一次只能装一个，切换需卸载+重载 2–6s）。适合跑**实时重活**（生成、视觉、编码）。

> 关键洞察：主机"全常驻不切换"，副机"一次一个按需换"——这是由内存带宽 vs 显存容量的硬件特性决定的，不是配置能绕过的。

## 三级智能体分流

| 层级 | agent | 模型 | 职责 | 兜底 |
|---|---|---|---|---|
| **L1 决策** | main | 云模型（语义理解强） | 收任务 → 判断本地能不能做 → 能则派 L2，不能则自己干或问人 | 人是最终裁决者 |
| **L2 调度** | courier / secretariat | 本地 8B | 拆单 → 并行派发执行子件 → 收转汇总 | 做不了 → 返回 L1 问你 |
| **L3 执行** | 业务执行 agent | 本地 14B/8B | 干具体活（文档生成、识别、编码） | `__ESCALATE__` 上报 |

### 任务流（三种情况）

**情况 1：本地能处理**
```
你 → L1：判断"这活本地能干嘛？"
   → 能 → L2 拆单 → 并行 spawn 执行子件（指定 14B，别继承 8B CPU）
   → L2 汇总 → L1 → 你
```

**情况 2：本地处理不了**
```
L2 试后失败 → 返回 __ESCALATE__ + 原因
   → L1 不再自动上云，而是【问你】"本地做不了（原因X），要不要上云？"
   → 你决定：上云 / 换方案 / 放弃
```

**情况 3：本来就该云/你干**
```
L1 收 → 判断不必本地 → 直接处理或问你 → 不经过 L2
```

### L1 分流判断标准

收任务先问自己：
1. 需要 GPU/视觉/转码？ → L2 → 业务执行 agent（副机）
2. 需要检索/大宗文本？ → L2 → 本地 30B
3. 纯格式化/命名/做表？ → L2 → 本地 1.5B/8B
4. 复杂推理/长文/要质量？ → 自己（云端）或问人
5. 不确定本地行不行 → 交 L2 试，失败再问人

## 关键机制（已固化的铁律）

- **不做自动上云**：任何层 `__ESCALATE__` 或做不了 → 回 L1 问人。**人不拍板，不上云花钱。**
- **派活用一次性干净子会话**：常驻 agent 会话不适合多步分发（ctx 会累积溢出）→ 分发用 `spawn` 一次性子会话。
- **执行子件显式指定模型**：spawn 时会继承父模型，必须显式传 14B（GPU 快），别继承 8B CPU。
- **用完自动删**：所有 spawn 子会话带 `cleanup:"delete"`（回报即归档）+ 超龄自动归档（如 20 分钟），不留残留。
- **agent 间放行**：配置 agentToAgent 白名单（main ↔ 调度 ↔ 执行）。

## 为什么"人留最终裁决"

自动上云 = 无上限的成本风险。系统设计成"任何层搞不定 → 上报人类 → 人拍板（上云/换方案/放弃）"。

这是**成本护栏**，不是功能缺陷：机器负责执行和尝试，人负责价值和预算决策。
